# Tool security review

Galaxy reviews the command and configfile templates of tools for places where a value a user controls can
leave the quotes or the argument it is written into: a text parameter, a collection element identifier, a
dataset name or metadata element, a group tag, a dataset's content, a user preference. Nothing from the tool is
run: the templates are compiled with Cheetah's compiler and the resulting syntax tree is analysed. A process
that prepares jobs reviews a tool when it prepares the tool's first job, and keeps the review as long as it
keeps the tool.

Before a job's command line is built, the values of the job are compared with the tool's high and critical
findings. Two options in `galaxy.yml` control what happens then:

- `tool_security_review`: `enforce` (the default) fails a job whose value contains a character that can leave
  its place, `log` only logs a warning, `off` turns the review and the checks off.
- `tool_security_review_strict_when_unsure`: for jobs the review cannot check, `true` (the default) requires
  every value the job carries to be plain, and refuses every job of a tool none of whose values can be
  checked. `false` runs such jobs without a check.

A plain value has no quotes, no `$ ; & | < > \ ( ) { } [ ] % # *`, no newline or tab, no word that starts with
`-`, and none of Galaxy's sanitizer tokens such as `__gt__`.

To see what the review finds in a tool, run

```console
$ python -m galaxy.tool_util.security path/to/tool.xml
```

## Refusal codes

Every refused job carries one or more codes: the message of the failed job ends with them
(`Refusal codes: shell-injection.`), and the warning Galaxy logs starts with them
(`Tool security review (shell-injection): job ...`).

The examples below are the cases of the review's declarative spec,
`lib/galaxy/tool_util/security/spec/`, which ships in `galaxy-tool-util`. Each case is a real tool XML file
and the jobs it refuses and runs. A job lists everything a template can read: parameter values (`inputs`),
datasets (`name`, `content`, `metadata`, `tags`), collections (element identifiers), the user's preferences,
and the review's settings (`config`). Galaxy's unit tests run every job through the evaluator that prepares
real jobs, in `enforce` and `log` mode. For the refused jobs that show `harm-marker`, they also build the
command with the review off and run it, to show that the value does harm without the review.

### `shell-injection`

A value can close the quotes around it, or is written unquoted, and start another shell command.

#### raw_text_shell_injection

A text value written past its sanitizer can close its single quotes and start a command.

Tool `raw_text_single_quoted.xml`:

```
echo '${word.value}' > '$out'
```

Refused

```
inputs:
  word: a';touch harm-marker;'
```

Runs: Command characters stay inside the quotes when no quote closes them.

```
inputs:
  word: a;b|c && d
```

#### element_identifier_shell_injection

Element identifiers are not sanitized; one in single quotes can start a command.

Tool `element_identifier_single_quoted.xml`:

```
#for $e in $input
echo '$e.element_identifier' >> '$out';
#end for
```

Refused

```
collections:
  input:
    elements:
    - identifier: a';touch harm-marker;'
```

Runs: Spaces, slashes, dots and a lone quote are common in identifiers and stay in place.

```
collections:
  input:
    elements:
    - identifier: sample 1/reads.fq
    - identifier: Bob's reads
```

#### group_tags_shell_injection

Group tags are not sanitized.

Tool `group_tags.xml`:

```
#for $g in $input.groups
echo '$g' >> '$out';
#end for
```

Refused

```
datasets:
  input:
    tags:
    - group:a';touch harm-marker;'
```

Runs

```
datasets:
  input:
    tags:
    - group:treated
    - name:sample1
```

#### dataset_content_shell_injection

A template that reads a dataset with open() writes its content; the check reads the file Galaxy keeps.

Tool `dataset_content_first_line.xml`:

```
#set $first = open(str($input)).readline().strip()
echo '$first' > '$out'
```

Refused

```
datasets:
  input:
    content: 'a'';touch harm-marker;''

      '
```

Runs

```
datasets:
  input:
    content: 'chr1 100 200

      '
```

### `nested-interpreter`

A value is written into the program of another interpreter (`bash -c`, `sed`, `perl -e`, ...) and can change what that program does.

#### nested_shell

A value in the program of `bash -c` is shell code again, inside the outer quotes.

Tool `nested_shell.xml`:

```
bash -c 'echo ${word.value}' > '$out'
```

Refused

```
inputs:
  word: a;touch harm-marker
```

Runs

```
inputs:
  word: hello world
```

#### sed_program

A value in a sed program can end the s command and add one that runs a shell command (`e`, GNU sed).

Tool `sed_program.xml`:

```
echo x | sed 's/x/${word.value}/' > '$out'
```

Refused

```
inputs:
  word: 'y/;e touch harm-marker

    s/x/'
```

Runs

```
inputs:
  word: hello world
```

### `configfile-injection`

A value is written into a configfile that a script runs and can end its string and add code.

#### configfile_python

A value in a string of a Python configfile can end the string and add Python code.

Tool `configfile_python.xml`:

```
python3 '$script' > '$out'
```

Refused

```
inputs:
  word: ''';open(''harm-marker'',''w'');'''
```

Runs

```
inputs:
  word: a;b "c" $d
```

### `stray-quote`

A quote in one value is harmless by itself but flips the quoting of the rest of the line, which leaves the command characters of another value unquoted.

#### stray_quote

A lone quote in one value is harmless by itself, but it flips the quoting of the rest of the line, which leaves the command characters of the next value unquoted.

Tool `stray_quote.xml`:

```
#for $e in $input
echo '$e.element_identifier' >> '$out';
#end for
echo '${word.value}' >> '$out'
```

Refused

```
inputs:
  word: x;touch harm-marker;#
collections:
  input:
    elements:
    - identifier: Bob's reads
```

Runs: The same value with no quote before it stays inside its quotes.

```
inputs:
  word: x;touch harm-marker;#
collections:
  input:
    elements:
    - identifier: Bobs reads
```

Runs: The same lone quote next to a value without command characters.

```
inputs:
  word: it's fine
collections:
  input:
    elements:
    - identifier: Bob's reads
```

### `not-plain-unchecked-place`

The tool writes values in places the review cannot judge (parts of the template it did not follow, or values it cannot trace), and a value is not plain.

#### not_analysed_strict

Where the review does not follow parts of a template, it cannot tell which characters do harm, so every value the template reads must be plain.

Tool `search_list.xml`:

```
#for $e in $input
echo '$e.element_identifier' >> '$out';
#end for
echo '$searchList' > /dev/null
```

Refused

```
collections:
  input:
    elements:
    - identifier: a';touch harm-marker;'
```

Refused: Even a character that is harmless where the value is written.

```
collections:
  input:
    elements:
    - identifier: a;b
```

Runs

```
collections:
  input:
    elements:
    - identifier: sample 1/reads.fq
```

Runs: An administrator can run such jobs unchecked.

```
collections:
  input:
    elements:
    - identifier: a;b
config:
  strict_when_unsure: false
```

### `not-plain-check-error`

Comparing the job's values with the review failed, and a value is not plain.

#### check_failed

When comparing a job's values with the review fails, every value must be plain.

Tool `raw_text_single_quoted.xml`:

```
echo '${word.value}' > '$out'
```

Refused

```
inputs:
  word: a;b
fault: check
```

Runs

```
inputs:
  word: hello
fault: check
```

### `uncheckable-review-failed`

The review of the tool failed, so nothing is known about what its templates do.

#### review_failed

A tool whose review fails cannot have any job checked.

Tool `raw_text_single_quoted.xml`:

```
echo '${word.value}' > '$out'
```

Refused

```
inputs:
  word: hello
fault: review
```

Runs

```
inputs:
  word: hello
config:
  strict_when_unsure: false
fault: review
```

### `uncheckable-rewrites`

The templates change values in ways that can bring back characters the sanitizer took out (`.replace`, `re.sub`, `chr()`, a decoder).

#### rewrites_restore_tokens

A template that turns the sanitizer's tokens back into quotes and redirects undoes the sanitizer.

Tool `rewrites_restore_tokens.xml`:

```
echo '${str($word).replace("__sq__", "'").replace("__gt__", ">")}' > '$out'
```

Refused

```
inputs:
  word: x' >harm-marker '
```

Refused: Even a plain value.

```
inputs:
  word: hello
```

Runs

```
inputs:
  word: hello
config:
  strict_when_unsure: false
```

### `uncheckable-template-code`

The templates run Python that can read text the job does not carry (imports, `open()`, `$__app__`, the models behind `.unsanitized`).

#### raw_dataset_model

A template that reads the dataset model behind `$input.unsanitized` can read text the job does not carry, so no value counts as plain.

Tool `raw_dataset_model.xml`:

```
echo '${input.unsanitized.name}' > '$out'
```

Refused

```
datasets:
  input:
    name: a';touch harm-marker;'
```

Refused: Even a plain name.

```
datasets:
  input:
    name: reads
```

Runs

```
datasets:
  input:
    name: reads
config:
  strict_when_unsure: false
```

#### template_code

A template that imports code can read text the job does not carry, so no value counts as plain.

Tool `template_code.xml`:

```
#import subprocess
echo '$word' > '$out';
echo '$searchList' > /dev/null
```

Refused

```
inputs:
  word: hello
```

Runs

```
inputs:
  word: hello
config:
  strict_when_unsure: false
```

### `uncheckable-letters-are-code`

Letters alone can be code where the tool writes a value: the program to run, text piped to a shell, or unquoted Perl or Ruby code.

#### pipe_to_shell

A value in text piped to a shell is code whatever its characters, so every job is refused.

Tool `pipe_to_shell.xml`:

```
echo 'echo ${word.value}' | sh > '$out'
```

Refused

```
inputs:
  word: a;touch harm-marker
```

Refused: Even a plain value.

```
inputs:
  word: hello
```

Runs

```
inputs:
  word: hello
config:
  strict_when_unsure: false
```

#### command_position

A value that names the program to run is code with letters alone.

Tool `command_position.xml`:

```
$program > '$out'
```

Refused

```
inputs:
  program: touch harm-marker
```

Runs

```
inputs:
  program: echo
config:
  strict_when_unsure: false
```

### Jobs that run

Values the review lets through, where a check that is too strict would refuse common names.

#### sanitized_text_stays_quoted

The default sanitizer turns quotes into tokens, so a sanitized text value cannot leave its quotes.

Tool `sanitized_text_single_quoted.xml`:

```
echo '$word' > '$out'
```

Runs

```
inputs:
  word: a';touch harm-marker;'
```

#### dataset_name_stays_quoted

Outside a collection, the element identifier of a dataset input is its name, which Galaxy sanitizes. The review counts it as written as the user set it; the job check reads it as the template does.

Tool `dataset_name_identifier.xml`:

```
echo '$input.element_identifier' > '$out'
```

Runs

```
datasets:
  input:
    name: a';touch harm-marker;'
```

#### wrapped_names_stay_quoted

Galaxy sanitizes dataset names and metadata read through the dataset wrapper even in a tool that turns the sanitizer off. The review counts them as written as users set them; the job check reads them as the template does, so these jobs run.

Tool `dataset_name_unsanitized.xml`:

```
echo '$input.name' '$input.metadata.column_names' > '$out'
```

Runs

```
datasets:
  input:
    name: a';touch harm-marker;'
    ext: tabular
    content: "1\t2\n"
    metadata:
      column_names:
      - a';touch harm-marker;'
```

#### user_preference_stays_quoted

Galaxy sanitizes what a template reads from the user object, preferences included. The review counts a preference as written as the user set it; the job check reads it as the template does, so this job runs.

Tool `user_preference.xml`:

```
echo '${__user__.extra_preferences.get("spec|label", "")}' > '$out'
```

Runs

```
user:
  preferences:
    spec|label: a';touch harm-marker;'
```
